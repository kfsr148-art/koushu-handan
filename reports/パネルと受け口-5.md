# パネルと受け口-5 — 「写せます（N件）」の押し送りの可否と手順（実装はしていない）

**VAIO 2026-08-30 03:xx ／ 何も書き換えていない（調べのみ）**

**結論** ── **出せる。ただしパネル側からは出せない。見張り側（`watch-notify.ps1`）から出す。**
道具は既にある（ntfy）ので、**新しい仕組みは要らない**。
指示どおり**実装は止めてある**。下の手順で進めてよいか決めてほしい。

---

## 1. パネルに通知の仕組みは無い

`panel.html` を調べた結果、**押し送りに関わる物は一つも無い**。

| 探した物 | 件数 |
|---|---|
| `Notification`（ブラウザの通知） | **0** |
| `serviceWorker` / `ServiceWorker` | **0** |
| `pushManager` / `webpush` | **0** |
| `manifest`（ホーム画面へ追加する札） | **0** |

パネルが外へ出す口は **`fetch` の八箇所だけ**で、いずれも**読み取り**
（L378 版／L462 ここまで読んだ／L490 板／L991 本体版／L996 stable 版／
L1053 知らせ／L1677 使用量／L1861 状態）。
**書く口も送る口も無い**——送る道具は **v11 で撤去済み**で、いまのパネルは「見る」ためだけの道具。

## 2. 既にある道 ── ntfy

iPhone への押し送りは、**見張りの側が既に毎日使っている**。

| 段 | 場所 |
|---|---|
| 投げる実体 | `~/.claude/watch-notify.ps1` **L617-619**（`curl.exe` で `https://ntfy.sh/<話題名>` へ POST） |
| 話題名 | `~/.claude/rc-ntfy-topic.txt`（19バイト・**公開リポジトリには絶対に書かない**） |
| 入口 | `Send-Ntfy` **L859** → `Send-NtfyNow` **L739** |
| 添える物 | `Title`（RFC2047 の Base64）／`Priority: 4`／`Click: ` **L511** のパネルの URL／`Cache: no`（ntfy 側に溜めない） |

**「写せます（N件）」も、この同じ道でそのまま出せる。** 新しい経路も鍵も要らない。

## 3. なぜパネル側からは出せないか

パネルが自分で ntfy へ投げれば、**転じた瞬間**も **N の正確な数**も手に入る。
だが **`panel.html` は公開物**で、投げるには**話題名を書き込むことになる**。
話題名は「知った者は誰でも読める・書ける」ので、**公開物に書けない**（この決まりは既に置いてある）。
非公開の置き場から読ませる道も無い（raw で読むには認証が要る）。

→ **パネル側は不可。見張り側から出す一択。**

＊もう一つの理由 … パネルは**開いている間しか動かない**。閉じている・寝ている端末へ届けるには、
　どのみち機械の側から投げる必要がある。

## 4. 出すならこう組む（手順）

**置き場所** … `watch-notify.ps1`。郵便詰まりの一発（L1536-1575）と同じ形。

1. **転じたことを見分ける**
   いまの状態は `state.json` の `stat`（作業中／ヨシ待ち／終わり／手待ち／異常）。
   **前の巡回で「作業中」、今の巡回で「作業中でない」**なら、押せる状態へ変わった回。
   ＊`watch-notify.ps1` は毎分回るので、遅れは最大60秒。
2. **N を数える**
   `notices.json`（公開側）の札から、`seen.json`（ここまで読んだ）より後の未処理を数え、
   板の二枠を足す。**パネルの「まとめて写す（N件）」と同じ数え方**を写す。
3. **一度だけにする**
   `~/.claude/copy-ready.txt` に印を置く（`mikomi-over.txt` L463 や
   `mailbox-stuck.txt` L464 と同じ流儀）。
   - 送ったら印を書く
   - **また「作業中」へ入ったら印を消す**（次に0件へ転じたら、また一度だけ鳴る）
   - **パネルを開き直しても鳴らない**（鳴らす判断は機械の側にあり、開閉と関係が無い）
4. **文面**
   ```
   題   : ✅ 写せます
   本文 : 写せます（N件）
   ```
   `Click` は今までどおりパネルの URL。

**工数の見込み … 30分**（書く25分＋実測5分）。触るのは `watch-notify.ps1` 一本。
作法29 の要に当たるので、**写しを取る → 直す → 構文検査 → 通らなければ戻す**の順を踏む。

## 5. 一つだけ、数が合わない見込みがある

**N は端末ごとに違う。** パネルの「まとめて写す（N件）」は、
その端末の **`localStorage` の「写した印」**（`panel.html` L406・L424）を引いた数。
この印は**端末の中にしか無い**ので、見張り側からは見えない。

- 見張りが出せるのは **`notices.json` ＋ `seen.json` から計算した数**
- 端末で既に何枚か写していれば、**押し送りの N のほうが多く出る**

**どうするか**（決めてほしい）

| 案 | 中身 | 差 |
|---|---|---|
| **甲** | そのまま「写せます（N件）」。N は機械の数え | 端末で写した分だけ多く出ることがある |
| **乙** | 数を出さず「写せます」だけにする | ずれない。ただし件数が分からない |
| **丙** | 「写せます（最大N件）」と断りを付ける | ずれても嘘にならない |

＊「ここまで読んだ」（`seen.json`・27バイト）は公開側にあるので、**そこまでは合わせられる**。
　合わないのは「押して写した分」だけ。

## 6. 代案（Web Push）を勧めない理由

iPhone のブラウザから直に通知を出す道もあるが、**採らないほうがよい**。

- **Service Worker が要る。** この決まりでは **`Service Worker` は入れない**（作法22）。
  理由は `ver.txt` 方式の更新と衝突し、古い本体を掴み続ける事故の温床になるため。
  押し送りだけの SW は目的が違うが、**同じ道具を入れることに変わりはない**。
- iOS では **ホーム画面へ追加した形でしか** Web Push が使えない。
  普通に Safari で開いているだけでは鳴らない。
- VAPID の鍵と、押し送りを投げる先が別に要る。**ntfy で足りているものを二重に持つことになる。**
