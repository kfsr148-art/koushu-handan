# 報告の残し方-1 — 報告を印ごとに reports/ へ残す

**VAIO 2026-08-30 01:xx**

`report-latest.md` は毎回上書きするので、前の報告の数字が押し出されて消える事故が起きていた
（`兎の攻守-4` の追補5〜8 の表が、続く 1〜4 の報告で消え、出し直しに一往復かかった）。
**印ごとの控えを `reports/` に残す形**へ変えた。

---

## 1. 何を作ったか

| 物 | 中身 |
|---|---|
| **`reports/`** | 印の名の `.md`。例 `reports/兎の攻守-5.md`。同じ印で二度書くときは末尾に `-2`・`-3` … |
| **`reports-index.js`** | `reports/` を新しい順に読んで一覧を組み、`report-latest.md` の末尾へ貼る道具 |
| **`CLAUDE.md` の作法33** | 報告を書くたびに控えを残し、一覧を貼り、push するところまでを決まりにした |

**一覧の範囲は新しい20件**（`reports-index.js` の `KEEP`）。全部の件数も一覧の頭に出る。
一覧は `<!-- 控えの一覧 ここから -->`／`<!-- ここまで -->` で囲ってあり、貼り直しても増えない。

一覧の各行は **raw の URL への繋ぎ**にしてある。

```
https://raw.githubusercontent.com/kfsr148-art/koushu-handan/main/reports/<印>.md
```

## 2. 途中まで済んだときの残し方（指示3）

**先に済んだ分をその印で残し、残りが済んだら `-2` で別に残す。**
今日の `兎の攻守-4` がちょうどこの形だったので、そのとおりに分けた。

| 控え | 中身 |
|---|---|
| `reports/兎の攻守-4.md` | **追補5〜8**（先に届いた分。上振れの余地の測定） |
| `reports/兎の攻守-4-2.md` | **1〜4**（後から再送された分。手牌の外の情報の棚卸し） |

## 3. 起こした控え

今日の報告を、`git` の履歴（各 commit の `report-latest.md`）から印の名で起こした。
**機械が書く「送った知らせ」の節は控えに残していない**（報告そのものだけを残す）。
書いた刻は commit の刻に合わせてあるので、一覧が時系列で並ぶ。

---

## 4. これから

報告を書くときは、毎回この順で行う。

1. `report-latest.md` を書く
2. 同じ中身を `reports/<印>.md` へ残す（同じ印の二度目は `-2`）
3. `node reports-index.js` で末尾の一覧を貼り直す
4. `reports/` ごと commit して push する
