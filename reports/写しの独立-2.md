# 写しの独立-2 — 済んだ札の写しを、作業の状態から切り離した（panel v84）

**VAIO 2026-08-30 05:45 ／ 本体（`koushu-handan.html`）には触っていない**

**釦の順序を「写すが先、予定表示が後」にした。** 押せる押せないを決めるのは、

### ①〜③ ── パネルと受け口-5 の「作業中は押せない」を置き換えた

v81〜v83 は作業中のあいだ「お知らせ」の釦と一覧を **`display:none` で畳んで**いた。
畳むと**済んだ札まで写せなくなる**——写せない理由が「まだ終わっていないから」ではなく
「作業中だから」になっていた。

```js
var n = buildBundle().count;
if (n > 0) {
  b.textContent = 'まとめて写す（' + n + '件）';   b.disabled = false; b.hidden = false;
} else if (busy) {
  …「作業中、HH時MM分終了予定」…                  b.disabled = true;  b.hidden = false;
} else {
  b.textContent = 'まとめて写す（0件）';           b.disabled = true;  b.hidden = true;
}
document.body.classList.remove('busy');
var cps = document.querySelectorAll('button.cp');
for (var i = 0; i < cps.length; i++) { cps[i].disabled = false; }
```

**予定の表示は「もう写す物が無い」ことの言い換え**であって、押させない理由ではない。

### ④ ── 頭の一行

```
作業中 1件：写しの網-1・札の題-1（報告の札が消えていた件と、札の題が古かった件）
```

出す名は札の題（`lastSubj`）＝**受けた枠の印**。控えを書き直す前は印そのもの、
書き直したあとは件名になる（札の題-1 で入れた仕掛けが決める）。

＊v78〜v83 の「未了 N件：（題）、（題）」は**題が種別しか語らない**ので、
　`未了 4件：🕒 延びています、🕒 延びています、🕒 延びています、🕘 定時の報せ` のように並び、
　何の件か分からなかった。

### ⑤ ── N と写る件数を一致させた（写しの網-1 の④）

v74〜v83 は板の行（あなた待ち・直近に終わった仕事）も `count` に足していた。
そのため釦の「N件」は**お知らせの札＋板の行**の合計になり、
**2026-08-30 の実測で札20枚に対して count は 23** だった。

**N は「押せば写る札の数」に揃えた。** 板の行は札ではなく添えの一行なので、
中身には入れたまま、数からは外す。

`buildBundle()` の中で `cards` の一枚一枚を `out` へ入れるたびに `count++` するので、
**`count` は必ず `todo.length` と等しい**。`copyBundle()` が落とすのも同じ `todo`。
**数えた N と、写る件数と、落ちる札の数が、常に同じ一つの値**になる。
