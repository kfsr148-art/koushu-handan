## 0. まず見つかったこと ── 台帳の刻が使えなかった

指示2は「実測は `reports/` と台帳（`orders-open.tsv`）の開始と終了から取る」だったが、
**台帳の受領時刻は使えない**。私が**手で打っている**ためで、実際にずれていた。

| | 刻 |
|---|---|
| **機械の本当の刻**（`date`） | **2026-08-29 23:08:57** |
| **台帳の最終行が打っている刻** | **2026-08-30 03:40** |

**約4時間半、先へずれていた。** 台帳の刻で所要を出すと、30件のうち **28件が負の値**になった
（例：`兎の攻守-1` は受領 18:35・控え 17:41 → **−54分**）。

**そこで、機械が打つ刻だけを使った** ── **報告を押し出した `commit` の刻の間隔**。
一つの窓で順に片付けているので、「前の報告を出してから次の報告を出すまで」がその一件に掛かった刻になる。
**枠を待っていた間も含むので多めに出る**——この断りは `estimates.js` の頭にも書いた。

## 3. 過ぎた時刻を出したままにしない

`panel.html` **L781-786**。当てた刻が既に過ぎていたら、**当てた分を足して先へ延ばす**。

```js
var nowSec = Math.floor(Date.now() / 1000);
if (endSec > 0 && endSec <= nowSec) {
  var step = (gm > 0 ? gm : 10) * 60;   /* 延ばす幅。当てが無ければ10分刻み */
  while (endSec <= nowSec && guard < 200) { endSec += step; guard++; }
}
```

釦の字は15秒ごとに組み直されるので、**過ぎた時刻が画面に残ることはない**。

## 4. ヨシ待ちなのに「作業中」と出ていた件

**原因** … v81 まで、作業中かどうかを**札の題から数え直していた**（`workingCards()`）。
`stateWord()` は題から読めない札を**すべて「作業中」に落とす**作りなので、
ヨシ待ちの札が立っていても、題から読めない札が一枚あれば「作業中」と出ていた。

**直し**（`panel.html` **L423**・**L766**・**L884**・**L1934**）

- `state.json` の **`stat`** を `lastStat` に控える（**L1934**）
- 釦の字も帯の畳みも `lastStat === '作業中'` で判じる（**L766**・**L803-806**）
- 未了の行も同じ判じにする（**L884**）

**状態は状態から読む**——札の題から数え直さない。
