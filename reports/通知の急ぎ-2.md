## 1. どちらにしたか ── **Ntfy-Visible の仕組みを掛けた**（固定の遅らせではない）

### なぜ早すぎたのか（記録で辿った）

**😽 は既に「公開側に出てから送る」形だった。** ただし待っていたのは**終わりの札**だけ。
**「写せます（N件）」の札は、その一巡あとに立つ。**

```
2026-08-30 13:34:04  急ぎの知らせに積んだ […]（名乗り done）
2026-08-30 13:34:43  公開側にまだ出ない（30秒）。次の回へ預ける
2026-08-30 13:35:04  預かっていた押し送り：公開側に出たので送る
2026-08-30 13:35:05  押し送りOK（HTTP 200）              ← 😽 が届く
2026-08-30 13:35:06  写せるようになったので一発知らせた：2件   ← ここで初めて写せますが立つ
2026-08-30 13:35:13  控えへ入れた […]
（公開はさらに約50秒後）
```

**理由** ── 状態が `作業中 → 手待ち` へ移るのは、鍵が `run: → done:` になるより**一巡遅い**。
写せますの札はその移り目で立つので、終わりの札より**約60秒あと**になる。そこから公開まで更に約50秒。

返事パネルの「残N／M件」は**写せますの札から M を読む**（v96）ので、
😽 が届いた時点では数が揃わない。ご覧になった「残1／2件 → 約1分後に 残2／2件」は、この形。

### 直し（`~/.claude/watch-notify.ps1` L706-733）

**固定で遅らせるのではなく、Ntfy-Visible と同じ仕組みを「写せますの札」にも掛けた。**

```powershell
function Ntfy-ReadyVisible([int]$since) {
  … 公開側の notices.json を読み、$since 以降で「写せます（N件）」を含む札が在れば $true …
}
# 押し送ってよいか。done だけは写せますの札も待つ。
function Ntfy-OkToPush([string]$state, [int]$since) {
  if (-not (Ntfy-Visible $since)) { return $false }
  if ($state -ne 'done') { return $true }
  if (Ntfy-ReadyVisible $since) { return $true }
  … $READY_WAIT（150秒）を過ぎたら、終わりの札だけで送る …
}
```

`Push-WhenVisible`（L737）と `Resume-Pending`（L762）の判定を、
`Ntfy-Visible` から **`Ntfy-OkToPush`** へ差し替えた。

**固定の75秒にしなかった理由。**

- 公開までの時間は**一定ではない**。写しの一回の実測で 42〜63秒、
  さらに写せますの札が立つのが**一巡（最大60秒）遅れる**ので、合計は 100〜130秒に振れる。
  75秒では足りず、余裕を見て固定値を大きくすると**速い回まで無駄に待たせる**
- **確かめてから送る仕組みが既にある**（😼 が使っている）。同じ物を使うほうが、
  数え方も待ち方も一箇所で済む

**待ちすぎない備え。** 新しく終わった分が0件の回は写せますの札が**そもそも出ない**
（写しの一回-2 の決め）。待ち続けると 😽 が黙るので、**`$READY_WAIT = 150`秒**を過ぎたら
終わりの札だけで送り、その旨を記録に残す。

＊`Ntfy-ReadyVisible` は**まとめ札の中でも当たる**（本文のどこでも探す）。
　通知の急ぎ-1 の `Flush-Quick` が done と ready を同じ回にまとめた回は、
　一枚の札に両方入るので**即座に真**になる。
