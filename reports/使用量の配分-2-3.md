## 直した式（`usage-widget.js` の `borderPct()`）

| | 前（切り捨て） | **後（切り上げ）** |
|---|---|---|
| 意味 | 済んだ分の物差し | **次の20:00境界までに許される割合** |
| 式 | `floor(経過÷24h)×100÷7` | **`ceil(経過÷24h)×100÷7`・上限100%・切り上げ0は1へ** |

```js
let days = Math.ceil((Date.now() - last) / 86400000);      /* 経過24時間の**切り上げ** */
if (days < 1) { days = 1; }                                /* 境目ちょうども最初の一日ぶんを許す */
return Math.round(Math.min(7, days) * 1000 / 7) / 10;
```

分への丸め（`resets_at` の小数秒と二物差しの1秒ずれの吸収）は前のまま。
関数の注記に「はじめは切り捨てで書いたが、それは済んだ分の物差しで、
この行が言いたい上限とずれていた」と経緯も残した。

## 実測 ── 三点

| 点 | 値 | 指示との一致 |
|---|---|---|
| **①いま（実時刻 20:39・8/30 20時台・実物の `resets_at`）** | **全体 100% ／ Fable 100%** | ✓ |
| **②リセット直後（8/31 20:01 の作り値）** | **14.3%**（切り上げ1 → 1×100÷7） | ✓ |
| **③境目前（8/30 19:48 の作り値）** | **全体 85.7% ／ Fable 85.7%** | ✓ |

＊②は **`resets_at` が翌週（9/7 20:00）へ進んだ想定の作り値**で測った。
　リセットの瞬間を過ぎれば `resets_at` は次の週を指すので、これが実際の姿。
　**`usage.json` がまだ古い（前の週の `resets_at` のままの）あいだは 100% と出る**——
　取得は10分ごとなので、この窓は最長10分。値が進めば 14.3% に変わる。

＊（参考）リセットちょうど（8/31 20:00:00）は切り上げ0→1の引き上げで **14.3%**…ではなく、
　実物の `resets_at`（8/31）で測ると 100%（7日目の枠の最後の瞬間）。どちらの物差しに
　載るかは `resets_at` がいつ進むかで決まり、上の窓の話と同じ。
