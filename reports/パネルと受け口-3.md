## 4. 「指示を受けた」の時刻の出どころと直し

**出どころ**

| 段 | 行 | 中身 |
|---|---|---|
| 書く者 | `~/.claude/inbox-feed.ps1` **L63-93** | **UserPromptSubmit のフック**。`$d.prompt` があれば刻と冒頭40字を `last-order.txt` へ書き、`state.json` の `orderAt`／`order` へ差し込む |
| 読む者 | `~/.claude/inbox-watch.ps1` **L398-409** | `last-order.txt` を読んで `state.json` を組み直す回にも入れ直す |
| 出す者 | `panel.html` **L1878-1886** | `state.json` の `orderAt` から `HH:MM` を取り、作業中のときだけ四行目に出す |

**なぜ古い値が出たか** … このフックは **UserPromptSubmit** なので、**この窓へ入る文はすべて通る**。
背後の仕事が終わった知らせ（`<task-notification>`）も「指示」として控えられていた。
実際 `last-order.txt` は次のようになっていた。

```
2026-08-29 20:17:16
<task-notification> <task-id>befmbhxck</
```

`20:17` は**背後の仕事（投票欄の probe）が終わった知らせの刻**で、人からの枠の刻ではない。
枠組みの札を落とす処理は元々あったが、**落とした結果が空のときは元の本文へ戻す**作りだったため、
札しか無い回もそのまま控えられていた。

**直し**（`inbox-feed.ps1` **L88-118**）

```powershell
if (-not $body) {
  Note '機械の再呼び出しなので控えない（枠組みだけの回）'
} else {
  $one = ($body -replace '\s+', ' ').Trim()
  ...（今までどおり last-order.txt と state.json へ）
}
```

- **枠組みの札を落としたあとが空＝人からの枠ではない**回は、**控えない**。
- `return` は使っていない。この下に「未処理があれば Stop を差し戻す」処理が続くため。
- 写しを取った（`.bak-20260830`）。**構文OK（149行）**、**BOM 有り**のまま。

**＊いま出ている 20:17 は、次に枠が届いた時点で直る。** このフックは枠が入る瞬間に走るので、
　直した効き目は**次の枠から**。過去の値を遡って書き換えることはしない。
