# 訴えの見直し-1 — 退避が受けている間は、上限を訴えない

**状態** … 終わり／`pipe-check` の他の条件・一発の道・判定には触っていない

## ① `cards-full` を「退避が働いていない時」だけに絞った

**上限に張り付くこと自体は、いまや当たり前**（40枚で回っている）。
困るのは**押し出された札が消える**ときで、退避（`notices-archive.json`）が受けている間は消えていない。

**「退避が働いている」の見分け**

```
notices-archive.json がある
  かつ 中身が1枚以上ある
  かつ 24時間以内に書かれている（押し出しのたびに書き直されるため）
```

この三つが揃っていれば**訴えない**。欠けていれば今までどおり訴える（本文も
「**退避が働いていない**ので、ここから先は新しい札が立つたびに古い札が消える」に改めた）。

## ② 定時の数えから `rung` を外す — **既に入っている**

前の枠（訴えの数え方-1）で入れてあり、字面で確かめた。

```
daily-notice の除外 … 入っている（'  rung ' を数えない）
数える単位          … 種類の数（$kinds.Count）
```

## 作り値（本物の枝を字面のまま抜き出して回した）

```
(甲) 退避あり・40枚          → **訴えない**
(乙) 退避なし・40枚          → 訴える
(丙) 退避が24時間より古い    → 訴える
(丁) 退避あり・20枚          → 訴えない（そもそも上限でない）
```

## 実地

```
本物を一回 … cards-full の記録 26件 → **26件**（増えない＝訴えが止まった）
そのときの実態 … 札 40枚／退避 21枚・最後に書かれたのは 12:27
```

**定時の一行は、まだ「2件（cards-full・subj-gap）」と出る。**
定時が数えるのは**直近12時間ぶんの記録**で、そこに**古い cards-full の行（最後は 03:01:31）が
まだ残っている**ため。訴えそのものは止まっているが、**記録は消さない**（消すと後から辿れない）。

```
03:01:31 の行が窓から出るのは 15:01 以降
subj-gap の最後（01:31:26）が出るのは 13:31 以降
→ **次の 21:00 の定時では、どちらも窓の外**（21:00 の窓は 09:00 以降）
```

**次の定時では、この二つは数から消える。**新しい訴えが無ければ、**訴えの行そのものが出ない**。
