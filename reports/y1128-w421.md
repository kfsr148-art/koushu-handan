# 枠 四百二十一：雀魂を開いたまま、判定の声を iPhone のイヤホンで聞く

状態：止め・本人の手待ち（VAIO のファイアウォールの窓と、iPhone で頁を開く手）。**実機では確かめていない。** — 21:5x

## 選んだ道：iPhone の Safari で VAIO の頁を開き、流し続ける音を聞く
訳：アプリを入れずに済み、本人の手が一番少ない。ふつうの音の部品（`<audio>`）は、ほかのアプリを手前にしても鳴り続ける事がある（Web Audio は切り替えで止まる不具合の報告がある）。VAIO はいつも無音を流し、判定の声をその中に挟むので、裏で新しく鳴らし始める動きが要らない。
**弱い所（どれも実機で未確認）**：雀魂が iPhone の音を独り占めすると止まるかもしれない／Safari が音を溜めてから鳴らすので数秒遅れるかもしれない／同じ Wi-Fi でないと届かない／iOS の版で裏の扱いが違う。

## 並べた道
| 道 | 良い所 | 悪い所 |
|---|---|---|
| Safari の頁＋流し続ける音（**選んだ**） | アプリ不要。手は許可1回と、頁を開いて1回押すだけ | 上の弱い所 |
| Safari の頁が知らせを受けて、その時だけ鳴らす | 通信が軽い | 裏に回ると頁の処理が止まる・音が割り込まれる恐れが高い |
| ntfy の通知 | 入れてあれば手が少ない | 通知の音はアプリに入っている音だけで、声は届けられない |
| SonoBus などの「PC の音を送る」アプリ | 音を送るための物で遅れが小さい見込み | iPhone にアプリ、VAIO にアプリと音の通り道のドライバー（管理者）。裏で雀魂と一緒に鳴るかは未確認 |
| VAIO から通話（LINE・FaceTime・Discord 等） | 裏でも確実に鳴りやすい | VAIO 側の通話の用意と音の通り道が要る。通話の扱いで雀魂とイヤホンの音が変わる見込み |
| iPhone の通知の読み上げ | 何も作らない | AirPods・Beats で画面に鍵がかかっている時だけ（センコの調べ） |
| VAIO を iPhone の Bluetooth の相手にする | — | iPhone は Bluetooth のスピーカー役にならない |

下の4つの「悪い所」のうち、通話と SonoBus の裏の動きは調べ切っていない（見込み）。調べた元：WebKit の不具合の記録（bugs.webkit.org 276016・283419・198277）、SonoBus の案内（sonobus.net）、iOS の通知音の決め。

## 作った物（手元の `uxplay-extra` だけ。本体・判定・見本・見分け・窓の置き場は変えていない）
- `voice-stream.js`：待ち受け 8720。出すのは「聞く頁」と音の流れの二つだけ。
- `mirror-helper.js`：本体が組んだ声（WAV）を Edge の中で AAC（48kHz・96kbps。Windows の変換はこの形だけ）にして流れに挟む。**VAIO から鳴らす道はそのまま。** 控え `.bak-w421`。

## 測り（VAIO の中だけ・iPhone は使っていない）
- VAIO の声の鳴り始め → AAC に変える 0.56〜0.58秒 → 声の最初の部分を送り出すまで +0.04秒。**VAIO の声より約0.6秒遅れて流れに乗る。**
- 試しの聞き手が受けた流れ 31.1秒を枠ごとにたどった：崩れ0・声の幅 24.7秒（元の声 24.8秒）。
- **iPhone に届いて耳で聞こえるまでの遅れは未測定**（Safari の溜めは実機でしか分からない）。

## 本人の手
1. VAIO の「Windows セキュリティの重要な警告」（Node.js）の窓で、**「プライベート ネットワーク」だけ**にチェックして「アクセスを許可する」（確認の画面は「はい」）。＊この許しは、この VAIO の node 全部が家の中の網で待ち受けられるようになる。
2. iPhone の Safari で `http://192.168.0.18:8720/` を開き「聞き始める」を押す → そのまま雀魂を開く（イヤホンは iPhone につなぐ）。VAIO の番号が変わった時は `%LOCALAPPDATA%\uxplay-extra\helper.log` の「iPhone で聞く頁」の行を見る。
