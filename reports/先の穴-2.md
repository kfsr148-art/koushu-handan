# 先の穴-2 — 押し出した札を残し、件名を機械が書き、訴えを画面に出す

**状態** … ①は**塞げない**（下記）／②〜⑥は済み。判定と札の作りには触っていない

## ① 写した印を公開側へ — **できない。実装せず報告する**

**パネルは公開側へ書けない。**

- `panel.html` にあるのは **`fetch(… , {cache:'no-store'})` の GET だけ**で、
  **POST は一つも無い**（10箇所の fetch を全部見た）
- GitHub Pages は**静的**なので、受け取る先が無い
- 唯一の書ける道は **ntfy へ POST** することだが、**話題名を持たせるには
  `panel.html`（公開）へ書く**ことになる。話題名を公開の置き場に載せないのは動かせない決めなので、この道は採れない

**よって、写した印はいまも `localStorage`（その端末の中）にしかない。**

＊`copied.json` を**読む側だけ**は入れてある。将来この印が置かれれば、②はその日から
　「写した札は移さない」に変わる（`notify-record.ps1` が `copied.json` を先に読む）。
＊塞ぐには**受け取る先**が要る（小さな受け口を一つ立てる等）。**土台の外の話**なので、
　やるかどうかは決めてもらう要がある。

## ② 押し出す札を、消す前に移す

`notify-record.ps1` が上限（40枚）で札を切るとき、**切る分を `notices-archive.json` へ移してから**切る。

- **直近200枚**を保つ。新しい順。同じ刻の札は二度移さない
- **`copied.json` があれば、そこに載っている札は移さない。**無い間は**全部移す**
  （消えるより、二重に残るほうが安い）
- 中身も形も `notices.json` と同じ（`title` / `time` / `message`）。**置き場が別なだけ**で、札の作りには触っていない
- 公開側にも置く（押しの対象に `notices-archive.json` を足した）

**パネルの「過去の札」（v118）** … `🗄 過去の札` の箱を足した。**開いたときに初めて**
`notices-archive.json` を取りに行き、新しい順に並べる。中の札は今までの箱と同じで、
押せば本文が開き、「写す」で写せる。取れない回は頭の字だけ「読めません（もう一度押す）」にして、画面は壊さない。

## ③ 控えの件名を、機械が書く

`inbox-feed.ps1` が枠を受けた場で、`work-note.txt` の **`件名:` の行だけ**を差し替える。

- **枠を受けた場が、切り替えの時点そのもの**なので、ここで書く
- **指示の回だけ**書く。問いかけ（`kind=ask`）では触らない
  （「いま生きていますか」で、走っている仕事の件名を消さないため）
- 60字で切る。ほかの欄には手を触れない

**作り値（本物の枝を字面のまま抜き出して回した）**

```
(甲) 指示の回     → 控えの一行目が「件名: 先の穴-2＝土台に触らず五つを塞ぐ」に変わった
(乙) 問いかけの回 → 控えの一行目は**そのまま**（触っていない）
```

  **「⚠ 知らせの道が落ちています … 〈中身〉」**の赤い一行を黄色の行の下に出す

## ⑤ 最後に受けた枠を、一行で出す

パネル（v118）の黄色の行の下に **「最後に受けた枠：〈題〉 HH:MM」** を出す。

- **状態に関わらず必ず出す。**送ったのに題が古いままなら「**届いていない**」と分かる
- 読む元は `state.json` の `order` と `orderAt`（`inbox-feed.ps1` → `last-order.txt` が書く）
- 題は34字で切る（長い枠がそのまま流れないように）

　こちらは題つきで、**いつでも**出る。
