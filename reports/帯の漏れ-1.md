# 帯の漏れ-1 — 重い帯を pre-push 自身に持たせた

**状態** … 終わり／土台（本体・パネルの判定・見張りの札の作り）には触っていない

## 何が漏れていたか

帯は**手で書く手順**だった。18:23:45 に手で帯を書き、押しを起こし、**18:33:30 に手で帯を消した**。
ところが**検査（`check-all --fast` の msedge）は 18:46 頃まで走っていた**。
つまり **18:33〜18:46 の13分は、いちばん重い時間なのに帯の外**だった。

その13分に何が起きたかは、予定表の記録がそのまま示している。

```
18:34:41  巡回が始まる（この回が終わらないまま居座る）
18:30:58〜18:47:58  見張りの起こしが毎分 ID=322（前の回がまだ走っているので見送り）
18:40:05  生存が ID=329（実行時間の上限で終了させた）
18:48:03  見張りが ID=329 で殺され、ここでようやく次が動いた
```

**巡回 18:34:41 → 18:46:25（11分44秒）／生存 18:29:19 → 18:48:15（18分56秒）の穴。**

## 直した形 — 入口で書き、出口で必ず消す

`.githooks/pre-push` に帯の開け閉めを持たせた。**手順に頼らない。**

```sh
trap heavy_off EXIT INT TERM
heavy_on
```

- **入口** … `heavy_on` が `heavy-on.ps1 -Why 'pre-push の検査'` を打つ
- **出口** … `trap … EXIT INT TERM` で、**通っても・落ちても・途中で止められても** `heavy-off.ps1` を打つ
- **持ち主だけが消す** … 入口で既に `heavy.txt` があれば、**書かないし消さない**。
  手で開けた帯や、別の重い仕事の帯を横から消さないため
- **帯が作れなくても push は止めない** … PowerShell が見つからない等でも `return 0`。
  帯は検査の結果に関わらないので、押しの可否には影響させない

併せて `heavy-off.ps1` を**消せないとき用に**直した。18:11 に「使用中」で消し損ねたため。
5回まで 0.4秒おきに試し、それでも駄目なら**刻を2時間前へ落として効力だけ切る**
（`heavy.txt` は30分で切れる作りなので、刻を古くすれば消したのと同じになる）。

## 作り値（写しに probe。本物の hook は触っていない）

`.githooks/pre-push` の写しを取り、検査の行だけ `sleep 12` に替えて回した。

```
(甲) 帯なしから回す・通る回      → 最中は帯が出ている → 終わって **自動で消えた**（戻り値0）
(乙) 検査が落ちる回              → 最中は帯が出ている → 落ちても **自動で消えた**（戻り値1）
(丙) 途中で止めた回（TERM）      → 最中は帯が出ている → 止めても **自動で消えた**
(丁) 既に別の帯が出ているとき    → 入口の知らせは **0回**（書いていない）／
                                   終わっても **他人の帯は残っている**
```

## 実地（本物の pre-push を一回回した）

**帯の間の起こし（19:19:50〜）**

```

関門（heavy-gate）が記録した見送り                … **0件**

```

## 実地で分かったこと — **見送りの主は関門ではなく予定表だった**

帯は出ているのに、**関門の見送りは0件**だった。理由は二つ重なっている。

1. **帯へ入って最初の一回は、関門が必ず通す**（`heavy-last-watch.txt` は帯の外で消えるため）。
   19:20:00 の回がこれで、**この回が走り出した**
2. その回が**重い検査の下で長引き**、以後の起こしは**予定表の側が 322 で全部見送った**。
   関門まで届かないので、関門の記録は増えない

**つまり、いま起こしを間引いているのは予定表の 322 であって、関門ではない。**
18:34 の穴も同じ形で、**関門を入れても、長引いた一回が居座る形は変わらない。**

塞ぐには「巡回そのものを短くする」「上限を延ばす」「重い検査のブラウザを1本に絞る」の
どれかになるが、**いずれも土台か作りに触るので実装せず、ここに書いて止める。**

＊**帯の効力は30分**。今回の検査は 19:19:50 → 19:41 の**約21分**かかっており、
　**30分に近い**。検査がこれ以上長引く日には、**帯が検査の途中で切れる**。
　伸ばすかどうかは決めてもらう要がある（`HEAVY_MAX_MIN`）。

## 直しの途中で踏んだ二つ（どちらも記録に残す）

### 一．**git が hook を呼ぶときの PATH に `powershell.exe` が無い**

手で `bash .githooks/pre-push` と打つと帯は出た。ところが **`git push` 経由では出なかった**。

```
20:14:24  押しの最中 … msedge 5本（検査は走っている）／帯は **無い**
```

`command -v powershell.exe` が git の hook の PATH では空になるためで、
こちらは「見つからなければ帯を作らず、押しは止めない」枝へ落ちていた。**黙って落ちる形**だった。

**決まった場所も当たるようにした。** `/c/Windows/System32/…/powershell.exe` と
`$SYSTEMROOT/System32/…` を順に見る。見つからないときは
**「powershell が見つからないので重い帯は作らない」と画面へ出す**（黙って落ちない）。

**実地（本物の `git push`）**

```
20:29:15  帯が **自動で出た**（git push 経由でも出るようになった）
20:5x     押しが終わり、帯が **自動で消えた**
```

### 二．**見張りの自動押しの `--autostash` が、手元の直しを飲み込んだ**

hook を直したあと、**その直しが消えていた**（ファイルが元の25行に戻っていた）。

犯人は `git-push.ps1` の押し直し。

```
$pull = @('-C', $Repo, 'pull', '--rebase', '--autostash', '-q', 'origin', 'main')
```

`--autostash` は**手元の未コミットの変更を退避して、rebase のあと戻す**。
ところが `Git-Run $pull 30000` と**30秒で切る**作りなので、切られると**戻しが走らない**。
退避は `stash@{0}: autostash` として残り、**手元からは消えたように見える**。

**取り戻した。**

```
git checkout stash@{0} -- .githooks/pre-push   → 54行が戻った
```

**教訓** … `~/.claude` の見張りが毎分押している以上、**このリポジトリで直したら、すぐ commit する**。
未コミットのまま重い仕事を挟むと、押し直しの退避に飲まれる。
＊退避はそのまま残してある（消すのは④取り返しのつかない削除に当たるため、勝手に消さない）。

### 併せて分かったこと … **見張りの自動押しは hook を通らない**

`git-push.ps1` は commit も push も **`--no-verify`** で打つ。
だから**毎分の自動押しでは検査も帯も走らない**。**帯が出るのは手押しのときだけ**でよい。
