## 方針（直す前に立てた一行）

**両者の読み書きを名前つきの `Mutex`（`Local\ClaudeStateJson`）で直列化し、
`inbox-feed` は錠の中で読み直してから自分の二鍵（`orderAt` / `order`）だけ差し替える。**

ご提示の二案のうち「**書く前に読み直して自分の鍵だけ差し替える**」を採り、
そこに**排他**を足した形。「一者に寄せる」を採らなかった理由は下記。

### なぜ「一者に寄せる」を採らなかったか

`inbox-feed` の差し込みを捨てて `inbox-watch` の全文書き直しに一本化すると、
**「指示を受けた」がパネルへ出るまで最大15秒遅れる**（巡回の間合い）。
いまは**その場で差し込む**ので、押してから約1分（Pages の反映を含む）で出る。
`inbox-feed` はフックで15秒しか猶予が無いので、逆に寄せることもできない。
**遅らせずに直せる**ほうを採った。

### 何が消えていたのか（直す前）

**消えるのは `orderAt` ではなく、相手の鍵。** そこが気づきにくかった。

- `inbox-feed` は先に `last-order.txt` を書き、**そのあとで** `state.json` を触る
- `inbox-watch` は毎巡 `last-order.txt` を**読み直して** `orderAt` を入れる（L398-409）

だから `orderAt` は両者とも持っている。**消えるのは `inbox-watch` 側の
`stat` / `subj` / `statAt` / `startedAt` / `mikomi` / `todo` / `at`** ——
`inbox-feed` が「読む→差し替える→書く」の**間に** `inbox-watch` が書くと、
その分が `inbox-feed` の古い写しで巻き戻る。

```powershell

try { $got = $mx.WaitOne(5000) }
catch [System.Threading.AbandonedMutexException] { $got = $true }   # 前の持ち主が落ちた
```

**決めごと。**

- **`Local\`** を使う（`Global\` は管理者の権限が要る）。二人とも同じ利用者の同じ場で走るので足りる
- **読み直しは錠の中**で行う。外で読むと、待っている間に古くなる
- **5秒で諦める。** `inbox-feed` はフックが15秒で切られるため／`inbox-watch` は15秒ごとに回るため。
  どちらも諦めても**次の回で入れ直せる**（控えの正は `last-order.txt`）
- **`Mutex` が作れない造りでは、今までどおり進む**（`catch` で `$got = $true`）。錠のせいで止めない
- **押し出し（`Git-CommitPush`）は錠の外**に置いた。押している20秒のあいだフックを待たせない
- 錠の名は**両方の台本にそのまま書いてある**。片方だけ変えないよう、双方の注記に明記した

## 実測 ── 三度やり直した

**一〜三度目は空振りした。理由は全部同じで、`Start-Job` の立ち上がりに1〜2秒かかり、
見込んだ順番どおりに走っていなかった。** 時計で待つのをやめ、
**B が読み終えた合図（札）を起点にする**形に組み替えて、ようやく再現した。

＊二度目の錠なしは**最後の姿が `B399`**（B は400回書いたのに）で、
　**消えていたのに「0回」と出ていた**。数え方そのものが間違っていた。ここは記録に残す。

### 決め打ちの順番で再現した（写しの上／`race4.ps1`）

段取り ── B（`inbox-feed` の形）が読む → **札を置く** → 400ms 眠る → 二鍵を差し替えて書く。
親（`inbox-watch` の形）は**札を待って**から、読んで全文を書く。

| | 錠 | Aが錠を取るまで | 最後の姿 | `stat`（Aの鍵） | `orderAt`（Bの鍵） |
|---|---|---|---|---|---|
| 1回目 | **なし** | 1ms | `{"orderAt":"B9","order":"b9","stat":"A0","at":0}` | **消えた** | 残った |
| 2回目 | **なし** | 1ms | 同上 | **消えた** | 残った |
| 1回目 | **あり** | **435ms** | `{"orderAt":"B9","order":"b9","stat":"A9","at":9}` | **残った** | 残った |
| 2回目 | **あり** | **429ms** | 同上 | **残った** | 残った |

**錠なしでは毎回 A の鍵が消え、錠ありでは毎回両方残る。**
錠ありの「429〜435ms 待った」が、**B が書き終えるまで待たされた実測**。

＊同時に各200回を12試行ずつ回す形（`race3.ps1` の【乙】）では、
　錠なし・錠ありとも 12/12 で両方残った。**ふだんの間合いでは滅多に当たらない**という意味で、
　「起きにくいが、当たれば必ず消える」種類の欠陥だった。
