## ① 譲りの判じの位置-1

### 段の順を組み替えた

```
（前）開始 → 帯の見回り → 鍵の見回り → 押し直し → …（重い段）… → 生存の合図 → 譲りの判じ

```

**合図は必ず先に打つ。** 軽い回は帯・鍵・押し直しの**三段を飛ばして**返る。
ふつうの巡回から10分の決め（`$LIGHT_MAX_MIN`）・敷居700MB（`$LIGHT_FREE_MB`）は触っていない。

### 13:21:18 の回が 11分 抜けられなかった理由

**上限はそもそも掛かっていなかった。** 二つある。

**（イ）`$STEP_MAX = 60` は止める力を持たない。** `Step` は**段が済んだ後に**経過を測り、
超えていれば足跡と `pipe-warn.log` へ一行書くだけの物差しで、走っている物を切らない。
**上限の外にある呼び出し**ではなく、**上限そのものが無かった**側。

**（ロ）足跡に出る名は「済んだ段」の名。** `13:21:18 帯の見回り +21.6秒` は
**帯の見回りが終わった刻**で、固まったのは**その次の段＝鍵の見回り**。
鍵の見回りは `kagi-watch.ps1` を子の powershell で起こす作りで、
**子が返らなければ親も返らない**。子には上限が無かった。

＊今朝の札（y0917-1450 の③）で「止まった段は帯の見回り」と書いたのは、この名の読み違い。
　**固まったのは鍵の見回り**が正しい。止まりの訴え（`$script:stallStep`）も同じ名を使うので、
　札には一つ手前の段の名が出る。

### 同じ直しで塞いだ所

子を起こす三箇所すべてに上限を掛けた（`Run-Child`）。返らなければ殺し、
足跡に「子の台本が N秒で返らないので切った（名）」を残す。

| 子 | 上限 | なぜその数字か |
|---|---|---|
| `heavy-off.ps1` | 30秒 | 綴りを一つ消して見張りの上限を戻すだけ。ふつう1秒以下 |
| `kagi-watch.ps1` | 20秒 | 会話の綴りの末尾512KBを読むだけ。ふつう1秒（今日の実測 +1秒） |
| `push-retry.ps1` | 90秒 | 中で git の押しが走る回がある。いちばん長い回に合わせた |

最悪でも 30+20+90＝140秒で返る。**前は上限が無く、11分でも返らなかった。**

### ついでに見つかった一行（直した）

割れた註の後ろ半分が `#` の外に出ており、**毎回 `Step '完了'` が余分に走っていた**。

```
（前）… 台本のいちばん終わり（# ---- 巡回の合図（2026-09-14・連携の穴-3 ②）----
      〔約80行あと〕
      Step '完了' の直前）で呼ぶ。      ← 註ではなく、走る一行だった
（後）#   ＊出すのは Flush-Quick。台本のいちばん終わり（Step '完了' の直前）で呼ぶ。
```

余分な `完了` は足跡の途中に出る。**止まりの見分けは「最後の行が完了か」で判ずる**ので、
ここから先で殺された回は「完了している」と読めてしまい、**止まりが見逃される**穴だった。

## ② done-stale-note の空振り-1

**写しが無い回でも、前の仕事の札が stop より前に立っていれば訴えない。**
黙って印だけ進め、記録（`pipe-warn.log`）へ一行残す。

```
done-quiet    前の仕事「〈名〉」の終わりの札は stop より前に立っている。立て直さず黙る（stop …）
```

**名の拾い方を変えた。** いまの枝は hook.log の「受け取った**指示**を控えた」を探していたが、
**いまの字は「受け取った**order（指示）**を控えた」**で、238行が古い字・178行が新しい字。
古い字だけを見ると、**何日も前の題を掴む**。そこで

1. まず退け先（`work-note-prev.txt`）の `前の件名:` を採る（stop より前でいちばん新しいもの）
2. 取れなければ hook.log の題へ落ちる（**二通りの字の両方**に当てる）

＊直したのはこの枝の中の新しい手だけ。**立て直しの側（同じ名の札があれば立てない）の
　古い字はそのまま**——別の枝なので触っていない。**あちらも同じ穴を持っている**ことは、
　ここに書き残しておく。
