# センコが影の課題を立てる道（確かめ画面の避け方）

状態：調べた（読むだけ・何も変えていない） — 09:21

## 結論

**推すのは (2) 橋の文書に「影の課題」の枠を書き、窓が `gh` で課題を立てる道。**
理由：センコの書き込みが確かめ無しで通ると分かっている唯一の場所が橋で、声の通話中でも動くため。

## (1) 確かめ画面を事前に許可する設定

- **設定そのものは在る。** コネクタの道具は一つずつ（または読む／書くの組ごとに）「Always allow／Needs approval／Blocked」を選べる。公式ヘルプで手順を読めたのは Team・Enterprise の持ち主の道（Organization settings > Connectors > 当のコネクタ > Tools）。個人（Max）の設定画面の手順は、公式の頁では確かめられなかった（確かめ画面の「Allow always」を押す道は remote MCP の文書に在る）。
- **ただし声の通話では効かない報告が続いている。** anthropics/claude-ai-mcp の課題 #493（開いたまま・Anthropic の返事なし）に、「Always allow にしても声の通話では Deny／Allow once だけの画面が出る。同じアプリの文字の会話では効く」が 11-04・11-08・11-20 の三件。保存した Always allow が Needs approval に戻る報告も複数（Max・iOS を含む）。
- **この窓から見える `issue_write` の仕様**（呼んでいない）：`method`（create／update）・`owner`・`repo` が必須、`title`・`body`・`labels` 等。確かめを飛ばす引数は無い。確かめは claude.ai の側の決めで、道具の側からは外せない。
- **試す値打ちのある一手（本人の手・1分）**：文字の会話で一度 `issue_write` を呼ばせ、「Allow always」を押す。それで文字の会話は通る見込み。声の通話で通るかは上の報告から当てにできない。

## (2) 橋の文書を通す道（手順）

**枠の書式**（センコが「窓へ（枠）」に書く。頭は今の形のまま＝`bridge-pick.js` を直さずに拾える）

```
枠 〈番号〉（〈月-日 時:分〉 センコ）影の課題
題：〈課題の題〉
本文：〈影の走り手に読ませる枠。読むだけの仕事〉
済みの条件: 含む:〈字〉   ← 無ければ本人のヨシ待ちで残る（shadow-run.js の今の決め）
```

**窓が何をいつ作るか**

1. 合図（枝 `senko`）か「橋」で起き、作法44 のとおり全文を読み `bridge-pick.js` に渡す。
2. 頭の行が「影の課題」で終わる枠は、ふだんの仕事にせず、次の一手だけ行う：
   `gh issue create --repo kfsr148-art/koushu-ops --label shadow --title "<題>" --body-file <本文＋済みの条件＋末尾に「橋枠: 枠 〈番号〉 〈月-日 時:分〉」>`
3. 枠の頭の下に「受領 〈刻〉 課題 #N」を書く（今の受領の行に番号を足すだけ）。
4. あとは今の常駐（3分おき）が拾って走り、結果を課題のコメントに書き、条件が○なら閉じる。

**二重に立てない印**（二段）

- 一段目：橋の「受領」の行。受領の有る枠は `bridge-pick.js` が出さない。
- 二段目：課題の本文の末尾の「橋枠: 枠 〈番号〉 〈月-日 時:分〉」。立てる前に
  `gh issue list --repo kfsr148-art/koushu-ops --state all --search "橋枠: 枠 〈番号〉 〈月-日 時:分〉 in:body"` で当たれば立てず、その番号で受領だけ書く（立てた直後に受領を書き損ねた回の備え）。

**課題が閉じたら橋に札を返す所**

- 軽い形（作り足し無し）：窓は立てた時に「窓から（札）」へ「枠 〈番号〉・〈刻〉：課題 #N を立てた」を一枚書く。結果はセンコが `issue_read` で直に読む（読む操作は確かめ無しで通る）。
- 厚い形：`shadow-run.js` が閉じた時に受信箱へ一行（「影の課題 #N 済」）を入れ、窓が起きてコメントの本文を橋の札に写す。`shadow-run.js` に手を入れる分だけ重い。**先に軽い形で足りるか見るのがよい。**

**弱い所**：窓が仕事中だと合図は受信箱に積まれ、課題が立つのは手すきになってから。影の走りは窓と別に動くのが売りなので、急ぐ課題ではここが遅れになる。

## (3) 他の道

| 道 | 確かめ | 危うさ |
|---|---|---|
| koushu-state の枝（`senko` と同じ形）に課題の中身を書いたファイルを置き、常駐が読んで立てる | 書くのは同じ GitHub のコネクタ（`create_or_update_file`）なので、**同じ確かめ画面が出るはず**。今の合図（bell.txt）が声の通話中に確かめ無しで書けているなら、その道具だけ許可済みという事なので要確認 | koushu-state は鍵なしで読めるリポジトリ。**枠の中身が公開される** |
| 橋の文書を公開にして、常駐が直に読む | 無し | 橋の全文（指示・札）が公開される。採らない |
| 常駐の `claude -p` に Claude Docs を読ませ、窓を通さず立てる | 無し | 窓の手すきを待たずに済むが、頭なしの走りで claude.ai のコネクタが使えるかは未確認。影の走り手の「読むだけ」の枠に書く手（`gh`）を足す事になる |
