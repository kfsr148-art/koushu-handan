## 4. 原因と直し

### 原因

`inbox-feed.ps1` は **L25 で `[Console]::OutputEncoding` だけ** UTF-8 にしていた。
**入力側は素のまま**で、`[Console]::In.ReadToEnd()` は ANSI（932）として読む。

1. Claude Code は枠の JSON を **UTF-8 の byte** で標準入力へ流す
2. `ReadToEnd()` が 932 として解く → 日本語が化ける
3. `ConvertFrom-Json` が転ぶ
4. **`} catch { }`** ── 何も言わずに握り潰す
5. `$d` は `$null` のまま → `$d.prompt` も空 → 控える節へ入らない

**半角だけの回（`task-notification`）は化けないので通る。** 20:17 の値が残っていたのはこれ。

### `last-order.txt` を書く者は一つだけ

`~/.claude` とリポジトリを総当たりで探した。**書く者は一つ。**

| | 場所 | 行 | 何をするか |
|---|---|---|---|
| **書く** | `~/.claude/inbox-feed.ps1` | **L33**（置き場）・**L104-137**（書き込み） | 刻と冒頭40字を書き、`state.json` へも差し込む |
| 読む | `~/.claude/inbox-watch.ps1` | **L398-409** | 読んで `state.json` を組み直す回に入れ直す |

**別の経路は無い。** 古い値が残り続けたのは、上書きする者が居なかったからではなく、
**唯一の書き手が黙って転んでいた**ため。

### 直し（`inbox-feed.ps1` L60-80）

標準入力を**生の byte で受け、UTF-8 として解く**形に替えた。符号化の設定に依存しない。

```powershell
try {
  $raw = ''
  try {
    $si = [Console]::OpenStandardInput()
    $ms = New-Object System.IO.MemoryStream
    $si.CopyTo($ms)
    $raw = [Text.Encoding]::UTF8.GetString($ms.ToArray())
    $ms.Dispose()
  } catch {
    # 生で読めない造りのときは、今までどおりの読み方へ落ちる
    $raw = [Console]::In.ReadToEnd()
  }
  $raw = $raw -replace '^\uFEFF', ''
  if ($raw -and $raw.Trim()) {
    $d = $raw | ConvertFrom-Json
    if ($d.stop_hook_active) { $already = $true }
  }
} catch { Note ('標準入力を解けなかった（' + $raw.Length + '字）: ' + $_.Exception.Message) }
```

**併せて `catch` を黙らせるのをやめた。** 転んだら字数と理由を `hook.log` へ残す。
**この穴を二日隠していたのは、空の `catch` そのもの。**

作法29の順で当てた ── 写し `.bak-20260830b` ／ 直し ／ `PSParser::Tokenize` **構文OK 167行**
／ **BOM 有り**（保たれている）。`inbox-feed.ps1` は毎回呼び直されるので、常駐の起こし直しは不要。
