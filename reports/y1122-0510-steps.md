## 二、stepsOf の挙動（panel-core.js）
- rows がある（`steps.rows` が配列）→ rows だけで数える：total＝行の数・done＝k が `x` の数・now＝最初の k≠`x` の段の字・nowK＝その k（` `／`雲`／`決`）・last＝最後の済み・next＝二つ目の未済。古い欄が食い違っていても rows が勝つ。空の rows は0段。
- rows が無い（steps が無い・null）→ stepTotal・stepDone・sNow・sDone・sNext（from: 'old'）。
- state-decide.js の decide と同じ数え方（作り値5通りで stepDone・stepTotal・sNow・sDone・sNext が揃う）。
- 使う所：`omoteLines`（段 N/M の行）・panel-view.js の `omoteGauge` の呼び手・`omote.panel.steps`・panel.html の `applySteps(d)`（読み込みのたびに lastStepTotal・lastStepDone・lastSNow・lastSDone・lastSNext を出す。部品が読めない時は古い欄へ落ちる）。endat.js の段も生の段を先に使う（`[雲]`・`[決]` も未済に数える。前は `[ ]`／`[x]`／`[X]` だけで、ゲージの区切りと段 N/M が食い違い得た）。

## 三、見込みの延びの扱い（endat.js）
- 実物：今の endat-base.json は `{start 04:27, mikomi0 40, steps0 3, mkAt 0}`。段が増えると「最初の見込み÷最初の段数（40÷3＝13.3分）×増えた段×比」で延びる。これは「一段の分」を過去の実測から取っているのではなく、**最初の見込みから取り、比（直近24時間の実測÷見込みの中央値）だけ実測**。
- 判断：書き替えが無い間はこのままが妥当（増えた段は実際の仕事。別の枠として積めば順番待ち×一枠の中央値で数えるのと同じ向き）。延び続けた本当の訳は、済んだ段が `[ ]` のまま残る・別の枠を同じ仕事に足す（窓の側・作法45）。
- 直した所：
  1. 見込みが書き替えられたら `mkAt＝その時の今`・`mkSteps＝その時の段の数`・`mkLeft＝その時の残り` を endat-base.json に一度だけ書く（今の刻は控えに一度書くだけなので指紋は毎分変わらない）。
  2. 書き替えの後は **その刻＋（新しい見込み＋その後に増えた段×（新しい見込み÷その時の残り））×比** で数え直す（前の見込みの延びは捨てる）。前は「仕事の始まりからの刻」と比べて遅い方＝窓が見込みを書き替えても縮まなかった。
  3. 古い控え（mkSteps が無い）は前の比べ方のまま。
- 作り値（--static の ⑤の二十七 六）：05:00 始まり・見込み40分・3段 → 05:40／段が6に → 06:20（延び）／05:30 に見込み20分へ書き替え（残り5段）→ 05:50／その後2段増え → 05:58（4分×2）／次の回も同じ刻。
