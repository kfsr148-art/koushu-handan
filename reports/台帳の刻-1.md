## 1. ずれの原因

**台帳（`orders-open.tsv`）へ書いている者は、機械の中に一つも居ない。書いていたのは私（Claude）で、
刻を `date` で取らずに手で打っていた。**

`~/.claude` とリポジトリを総当たりで探した結果、`orders-open.tsv` に触れる物は**四つ**あるが、
**四つとも読むだけ**で、書く物は無い。

| 物 | 行 | 何をするか |
|---|---|---|
| `~/.claude/board-emit.ps1` | **L28・L52-62** | 読んで「あなた待ち」の札を組む。**刻の欄（`$c[0]`）を `at` として使う** |
| `~/.claude/daily-notice.ps1` | **L32** | 読んで残り件数を数える（**刻は使わない**） |
| `state-line.js` | **L97-111** | 読んで残り件数を数える（**刻は使わない**） |
| `estimates.js` | — | 所要の計算に使っていた（**今回やめた**） |

つまり **`printf '%s\t…' "2026-08-30 03:40" …` の形で、私が字を打ち込んでいた**。
機械の刻を見ずに、話の流れから「このくらいだろう」と進めていたため、**時が経つほど先へ走った**。

**ずれは一定ではなく、広がっていた**（下の照合表）。差は **−14分から −357分**まで開いている。
一定のずれなら引き算で戻せるが、**広がるずれは戻せない**。

## 3. 直し

**これから** ── 台帳へ積むときは **`$(date '+%Y-%m-%d %H:%M')`** で取った値を入れる。
自分で時刻を書かない。この回の二行（`写せます-1`・`台帳の刻-1`）から実行している。

```
2026-08-29 23:22	写せます-1	…
2026-08-29 23:22	台帳の刻-1	…
```

**既にある行** ── **揃え直せない。**

- 真の受領時刻は**どこにも残っていない**。台帳が唯一の記録で、その台帳が狂っている。
- 郵便受け経由の枠なら `inbox.txt` に機械の刻が残るが、**今日の枠はほとんどが Code タブ経由**で、
  そちらは `last-order.txt` が**毎回上書き**されるため過去分が無い。
- ずれが**一定でない**（−14分〜−357分）ので、一律に足し引きしても直らない。
- 控えの `commit` の刻から逆算すれば「それらしい値」は作れるが、**それは実測ではなく作り値**なので入れない。

**代わりに境目を残した。** 台帳の末尾へ、読み手が飛ばす形（欄が1つなので
`board-emit.ps1` も `state-line.js` も `$c.Count -lt 4` で飛ばす）で一行入れた。

```
# ここから下の受領時刻は date で取った機械の刻（2026-08-29 23:2x から）。
  これより上の刻は手で打っており、機械の刻より最大約6時間ずれている
  （実測：直近20件で一致0件）。所要の実測に使わないこと。
```

＊`state-line.js` を回して、この行を足しても残り件数が変わらないことを確かめた（**残り3件**のまま）。
