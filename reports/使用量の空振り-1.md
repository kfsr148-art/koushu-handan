# 使用量の空振り-1 — 06:04 の取得は**成功していた**。本文が「枠の立っていない形」だった

**状態：終わり／本体（`koushu-handan.html`）には触っていない**

**結論** — 06:04 の取得は **HTTP 200 で成功**しており、`usage.json` も読めて中身も空ではなかった
（2193バイト・`at` は `2026-09-02T06:04:21+09:00`）。**空だったのは本文の値のほう**で、
**どの枠も `utilization` が 0、`resets_at` が null**（＝戻る刻が無い）という形が返っていた。
ウィジェットとパネルは、これを素直に「0%」「—」と描いていた。**数字を出さない形へ直した。**

**三つのどれだったか** — 「読めていた」。取得の失敗でも、空ファイルでもない。
`usage.json` は毎回きちんと書かれており、本文も JSON として読めていた。

**値そのものは偽だったか** — 断定はしない。03:06〜06:11 は**実際に手を動かしていない帯**
（前の仕事は 22:19 に終わり、次は 06:11 開始）なので、5時間枠が 0% なのは事実に合う。
ただし **seven_day が 11% → 0% へ落ちた**のは、直前の本文が「戻るのは 09-07」と言っていた
以上、七日ぶんの実績としては辻褄が合わない。**少なくとも週の行は当てにならない値**だった。

**害の中身** — 0% は「まだ余裕がある」と読める。**読めていないことが読み手に伝わらない**のが
いちばん悪い。戻る刻が「—」で出ていたのは、その唯一の手掛かりだった。

## ② 直し — 値の無い本文を 0% として描かない

**見分けは一箇所で行う。** 見張り（`watch-notify.ps1`）が本文を判じて、`usage.json` へ
**`empty`** と **`good`（最後に値の入っていた本文＋その取得の刻）**を書く。
ウィジェットとパネルは、この二つを読むだけにした——同じ見分けを二つの言語で書くと必ずずれる。

- **空の見分け** … `five_hour` / `seven_day` / `limits` の**どこにも `resets_at` が無い**こと。
  値が本当に 0% の回でも、枠が立っていれば戻る刻は入る（02:44 の実物で確認）。
- **控え** … 値の入った回に `~/.claude/usage-good.json` へ写す。空の回はそれを持ち回す。

出し方は三通り。

| 回 | ウィジェット | パネル |
|---|---|---|
| 読める | 今までどおり三行に数字 | 今までどおり三行に数字 |
| 空・控えあり | **控えの値**を出し、足元に「**HH:MM時点の値 ・ いまは取れていません**」（橙） | 同じ。足元に「**N時間前時点の値・いまは取れていません**」 |
| 空・控えなし | **数字を出さず**「使用量は取れていません／控えもありません」 | **箱ごと畳み**「使用量は取れていません（控えもありません）」 |

同じ形（`empty` と `good` を読む）へ直した。**panel v107**。
