## 直し — 「いちばん新しいフックが stop か」をやめる

[[札の抜け-1]] で分かったこと … 終わりの札は「巡回が鍵を `done:` と見た回」にしか作られない。
鍵は**そのときいちばん新しいフック**で決まるので、stop の 48〜102 秒あとに `notification` が来ると
鍵が `idle:` に化け、**札も押し送りも永久に作られない**。

```
書けた回 … stop 16:00:20 → 巡回 16:00:28（8秒後）／stop 06:55:28 → 巡回 06:55:41（13秒後）
落ちた回 … stop 16:21:55 →（76秒）／stop 16:46:54 →（48秒）／stop 18:17:30 →（102秒）
```

**毎分の巡回が隙間に当たるかという運任せ**だった。

**直したのは見方** — 「いちばん新しいフックが stop か」ではなく、
**まだ札にしていない stop があるか**で見る。

```
済んだ stop の刻を控える（done-said.txt）
  それより新しい stop があれば、あとから notification が来ていても done: として扱う
  ただし
    ・resume（新しい回の始まり）が stop より後にあるなら拾わない（次の仕事へ移っている）
    ・$FRESH_MIN（10分）より古い stop は拾わない（落ちる前の状態と区別が付かない）
  刻は **stop のもの**を使う（あとから来た notification の刻にしない）
```

＊拾い直した回は記録に残す … 「取り逃がしていた stop を拾った（刻・いまのフックは notification）」。

## 実測（写しに probe。本体には仕掛けを入れていない）

```
○ (甲) 76秒前に stop・そのあと notification のみ    → 拾う（＝落ちていた三回がこれ）
○ (乙) 8秒前に stop（今までどおり拾える回）          → 拾う
○ (丙) 同じ stop を既に札にしてある                  → 拾わない（二度出さない）
○ (丁) stop のあとに resume（次の仕事が始まった）    → 拾わない
○ (戊) 古すぎる stop（20分前）                       → 拾わない
○ (己) stop が一度も無い                             → 拾わない
```

**実地** — 見張りは毎分呼び直されるので、直しは既に効いている。
