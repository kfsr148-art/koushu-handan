## 1. なぜこの回だけ控えが書かれなかったか

**パネルの整理-3 の回に、控え（`work-note.txt`）を書き直さなかったから。**

以下、辿った跡。

```
2026-08-30 11:57:03  鍵 idle:11:38:19 -> run:11:56:31     ← パネルの整理-3 の走りが始まる
2026-08-30 12:01:03  鍵 run:11:56:31 -> done:12:00:54     ← 走りが終わる
```

この走りのあいだ、`work-note.txt` の中身は**前の回（パネルの整理-2）のまま一字も変わらなかった**。
見張り（`watch-notify.ps1` L249-258）は走り始めに控えの指紋を `note-at-start.txt` へ控えており、
**終わりの指紋と一致すれば「この回は一字も書いていない」と判ずる**。

```powershell
if ($hexNow -eq $startHash) { $r.stale = $true; $r.unwritten = $true }
```

そのため 12:01 の札はこうなった。

```
この間にまとまった知らせ 2本

［✅ 終わりました（返事不要）］
パネルの整理-2（板の跡地の状態の行を三通りへ）— panel v91
この回は控えを書いていません（前の回の控えが残っています。中身は当てになりません）。

［✅ 終わりました（返事不要）］
写せます（1件）
```

**件名が「パネルの整理-2」なのも同じ理由**——控えが前の回のままだったので、
そこに書いてある件名がそのまま札の題になった。

＊いまもこの状態が残っていた（この報告を書く直前に実読み）。

```
work-note.txt の件名 : パネルの整理-2（板の跡地の状態の行を三通りへ）— panel v91
```

**見張りの側は正しく働いている。** 落としたのはこちらで、
**パネルの整理-3 の回に控えを書き直さなかった**のが唯一の原因。
