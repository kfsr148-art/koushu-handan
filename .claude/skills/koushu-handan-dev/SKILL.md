# koushu-handan 開発の作法

このスキルは `koushu-handan.html` を編集する際の作法を定める。
以下を必ず守ること。

## 1. 対象ファイル

`C:\Users\user\Desktop\mahjong\koushu-handan\koushu-handan.html`

HTML・CSS・JavaScript・埋め込み資産が1ファイルに同梱された単一ファイル構成。
約8,700行あり、外部ファイルへの分割はしない。

## 2. 進行手順

**宣言 → ヨシ → 実装 → 納品** の順を厳守する。

1. **宣言** — 何をどう変更するかを先に説明する
2. **ヨシ** — ユーザーから承認語「ヨシ」を受け取る
3. **実装** — 承認後にはじめてコードを変更する
4. **納品** — 変更結果を報告する

承認語「**ヨシ**」を得るまで、実装に着手してはならない。
「いいね」「お願い」等は承認語ではない。ヨシが出るまで待つ。

## 3. 一応答一操作

1回の応答につき、操作は1つだけ行う。複数の変更をまとめて実行しない。

## 4. 頼まれていない改善を足さない

依頼された範囲だけを実装する。リファクタリング、命名の整理、コメント追加、
最適化などの「ついでの改善」は、明示的に頼まれない限り行わない。

改善案を思いついた場合は、実装せずに納品報告の中で提案するにとどめる。

## 5. 編集は str.replace で、置換前に一意性を確認する

単一ファイルに全てが入っているため、同じ字面が離れた場所に何度も出現する。
確認を怠ると無関係な箇所を壊す。

1. 置換対象の文字列を、まず **grep してヒット数を数える**
2. **1件であることを確認してから**置換する
3. 2件以上ヒットした場合は、前後の行を含めて範囲を広げ、
   一意になるまで置換文字列を伸ばす
4. 全件を意図的に置き換えたいときだけ、一括置換を明示的に使う

行番号は編集のたびにずれる。前の応答で調べた行番号を、そのまま次の編集に
使い回さないこと。編集の直前に取り直す。

## 6. 構文検証は node --check

`node --check` は JavaScript しか受け付けないため、HTML を直接渡しても検証にならない。

1. `<script>` ブロックの中身を一時ファイル（`.js`）に切り出す
2. `node --check <一時ファイル>` を実行する
3. エラーがないことを確認する
4. 一時ファイルは検証後に削除する

一時ファイルはスクラッチパッドに置き、リポジトリ内には作らない。
**構文検証は納品前に必ず1回行う。** 検証していない変更を納品と呼ばない。

## 7. キャラのセリフは既存を grep してから書く

キャラクターのセリフを追加・変更するときは、**書く前に**同じキャラの
既存セリフを grep して読む。

確認すべき点:

- 一人称と、プレイヤーへの呼称
- 語尾・口調（である／ですます／体言止め）
- 句読点や記号の使い方（「!」「〜」「…」の有無と量）
- 漢字を開くか閉じるか

思いついた口調で書き始めない。既存に合わせる。
既存と違う口調にしたい場合は、その旨を宣言の段階で伝えて承認を得る。

## 8. テスト用のシムは納品前に除去する

動作確認のために入れた仮の仕掛けは、納品前にすべて取り除く。

除去対象:

- 仮データ・ダミーの手牌・固定した戻り値
- 特定の分岐へ強制的に入れるためのフラグや条件書き換え
- デバッグ用の `console.log` / `alert`
- 一時的にコメントアウトした本来の処理（元に戻す）
- 検証用に足した表示要素

**除去したことを納品報告に明記する。** 何も入れなかった場合は「シムなし」と書く。

## 9. バージョン表記の同時更新

`data-ver` 属性と `verTag` div は、**必ず同時に更新する**。
片方だけを更新してはならない。

- `data-ver` — `<html lang="ja" data-ver="...">`（ファイル冒頭）
- `verTag` — `<div id="verTag">v...</div>`

起動時に `data-ver` を読んで `verTag` に反映し、さらに自身の HTML を取得して
`data-ver` を照合する更新チェック処理があるため、片側だけの更新は
バージョン不一致として表面化する。

更新後、両方の値が一致していることを grep で確認する。

## 10. 変更禁止

以下は変更不可。触れてはならない。

- `analyze()`
- `bestShapeOneSuit`

読んで参照するのは構わない。呼び出し方を変えるのも不可。
これらに手を入れないと実現できない依頼を受けた場合は、実装せずに
その旨を報告して指示を仰ぐ。

## 11. 納品後の commit と push

納品の後、**必ず GitHub に commit と push まで行う**。

commit メッセージは、**v番号と変更内容を一行で書く**。
